# Бэкапы и откат (`backup-rollback.md`) — как устроены копии и журнал изменений

Источник — DESIGN-v1.md §6.2, §8.1, §4.1 п.5. Этот файл отвечает на вопрос **«как именно»**: где лежат копии, что пишется в опись, как вернуть файл назад, что делать, если журнал оказался старого формата. Вопрос **«когда спрашивать и в каком порядке»** — в `consent.md` (пять шагов протокола); здесь он не повторяется, только используется.

## Где всё лежит

```
yunga-zhurnal/
├── changes.md                      # одна строка = одно изменение
├── backups/
│   ├── 2026-09-18_start/           # <дата>_<что>
│   │   ├── manifest.md             # опись: что скопировано и откуда
│   │   ├── settings.json
│   │   └── CLAUDE.md
│   └── 2026-09-18_dostup/
│       └── …
└── .gitignore                      # backups/ — внутрь не заглядывает ни git, ни публикация
```

Правила именования папки: **`<дата>_<что>`**, дата — `ГГГГ-ММ-ДД`, `<что>` — короткое латинское слово про повод (`start`, `dostup`, `razresheniya`, `huk`). Одна папка = одно событие протокола согласия. Не «всё в одну кучу за день»: если в один день две правки — две папки, иначе непонятно, из какой копии возвращать.

**Почему журнал лежит вне `~/.claude`** (в домашней папке, а не внутри настроек Claude): папка `.claude` защищённая, и при удалении плагина её содержимое может уйти вместе с ним. Бэкапы обязаны пережить удаление курса — иначе они бессмысленны.

## Как снимается копия

**Командой ОС, не инструментом `Read`.** Это принципиально: в `settings.json` и `.env` бывают секреты, и если снимать копию чтением, содержимое попадёт в переписку. Копирование их не показывает. Шаг с командой объявляется заранее — ученик увидит диалог разрешения на shell.

| Действие | Git Bash / sh | PowerShell |
|---|---|---|
| Копия файла | `cp "<откуда>" "<куда>"` | `Copy-Item "<откуда>" "<куда>"` |
| Размер в байтах | `stat -c %s "<файл>"` | `(Get-Item "<файл>").Length` |
| Контрольная сумма | `sha256sum "<файл>"` | `Get-FileHash -Algorithm SHA256 "<файл>"` |

Размер и сумма нужны не для красоты: по ним потом видно, вернулся файл ровно тот же или «почти тот же».

## `manifest.md` — опись копии

Лежит в каждой папке бэкапа. Формат — заголовок, дата со **временем и часовым поясом**, одна строка «как вернуть», таблица:

```markdown
# Копия перед <что делаем>

Снята <ДД.ММ.ГГГГ ЧЧ:ММ (пояс)> командой ОС, без чтения содержимого (`consent.md`, шаг 3).
Возврат: скопировать файлы обратно поверх оригиналов, затем сверить sha256.

| Файл | Откуда | Байт | sha256 |
|---|---|---|---|
| `<имя файла в этой папке>` | `<полный путь к оригиналу>` | `<число>` | `<сумма>` |
```

Столбцов ровно четыре и именно эти. «Откуда» — **полный** путь, иначе через месяц непонятно, куда возвращать. Одна строка на файл; пустая опись не создаётся — если копировать нечего, значит и правки нет.

Что обычно попадает в копию, по поводам:

| Повод | Файлы |
|---|---|
| Старт курса (1а, «польза №1») | `~/.claude/settings.json`, `~/.claude/CLAUDE.md` |
| Доступ к папкам (1б), разрешения (M02) | `~/.claude/settings.json` |
| Установка/снятие плагина, маркетплейсы | `~/.claude/settings.json`, `~/.claude/plugins/installed_plugins.json`, `~/.claude/plugins/known_marketplaces.json` |
| MCP-сервер (M10) | `.mcp.json` проекта |
| Хуки (M12) | `~/.claude/settings.json` |
| Обслуживание (M14) | настройки целиком, копия делается процедурой курса |

## Строка в `changes.md`

Одна правка — одна строка. Формат:

```
CH-NNN | дата+пояс | файл | что изменено | зачем | путь к бэкапу | как откатить | как проверено
```

`NNN` — сквозная нумерация с 001, не сбрасывается по этапам. «Как откатить» пишется человеческими словами, а не «см. бэкап»: через месяц читать будет ученик, а не Claude. Строка пишется **после** проверки, а не вместо неё.

## Откат: как вернуть

1. Ученик говорит `otkat` (без аргумента) — или Claude сам предлагает, если что-то пошло не так.
2. Claude зачитывает последние изменения из `changes.md` **словами**: «было → станет → что это изменит для тебя». Технический diff — только если ученик попросит.
3. Явное «да» — и здесь тоже. Откат такая же правка, как любая другая.
4. Файл(ы) копируются из папки бэкапа поверх оригиналов — снова командой ОС.
5. **Сверка sha256** с описью: вернулось ровно то, что копировали.
6. Новая строка в `changes.md` с пометкой «откат CH-NNN». Старая строка не стирается — журнал только дописывается.

### Сверка целостности после серии правок

В конце этапа (или в любой момент по просьбе) — сравнение живого файла с последней копией **по сумме, а не на глаз**. Расхождение сверх того, что записано в `changes.md`, — повод остановиться и разобраться: значения могли поменяться из другой сессии или самим Claude Code.

## Чего бэкап не покрывает — сказать прямо

- **`/rewind` не откатывает правки, сделанные через терминал** (checkpointing.md:70-72). Именно поэтому протокол требует править файлы инструментами `Edit`/`Write`, а не командами shell. Копия в `backups/` — это второй, независимый путь возврата, и после shell-правки он остаётся единственным.
- **Курс ничего не удаляет.** «Убрать» всегда означает «перенести в `Архив/` журнала». Удалённый файл бэкап не воскрешает, если копию не успели снять.
- **Удаление курса может унести `home.json`** — маленький файл в каталоге данных плагина, по которому `start` находит журнал. Если он потерялся, `start` сначала проверяет `~/yunga-zhurnal/`, а не найдя — спрашивает путь у ученика. Сам журнал при этом цел: он лежит в домашней папке и удалением плагина не затрагивается.
- **Откат установки через интерфейс Desktop — неполный.** Состояние маркетплейса хранится минимум в трёх местах, и кнопка «удалить» чистит не все (проверено вживую 18.09.2026). Разбор и порядок ручной дочистки — в `surface-steps.md`, раздел «Удаление».

## Журнал старого формата: поле `schema`

Автоматических миграций в курсе **нет** — сознательно. Вместо них у `progress.md` в шапке есть поле `schema` (версия формата журнала), рядом с `plugin_version`, `tz`, `surface`, `stage`, `current{module, step}` и отметками гейтов.

Что делает `start`, если `schema` в журнале не совпадает с той, которую ждёт установленная версия курса:

1. Говорит ученику прямым текстом: **«журнал старого формата»** — и что это не поломка и не его вина, курс просто обновился.
2. Открывает `CHANGELOG.md` курса и находит там **ручную инструкцию** для перехода с этой версии схемы на текущую.
3. Дальше — обычный протокол `consent.md`: **бэкап журнала → шаги из инструкции → строка в `changes.md`**. Никаких молчаливых правок файлов ученика «за него», даже когда изменение выглядит косметическим.
4. Ученик отказался обновлять формат — курс не настаивает и не блокирует: говорит, какие шаги в старом формате не сработают, и продолжает.

Что при этом гарантируется без всяких миграций: **идентификаторы модулей стабильны** (`M00`–`M15` и slug-и не переименовываются внутри версии 1.x — `reference/module-ids.md`), а прогресс пишется в журнал **после каждого шага**, а не в конце сессии. Поэтому даже брошенная посреди урока сессия не теряет больше одного шага.

Возврат капсулы после сжатия контекста хуком — это M12 (этап 3), и он не заменяет запись прогресса, а лишь избавляет от ручного пересказа.

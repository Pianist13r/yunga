# Установка по шагам (`surface-steps.md`) — какое окно, какая кнопка

Источник — DESIGN-v1.md §7.4 и живые итоги прогона установки (этап 0.5, 18.09.2026, Windows + Claude Desktop). Сюда ссылается README: здесь лежат сами шаги, там — только выбор пути. Пометка «проверено вживую» означает, что шаг реально прошли руками и записали результат; «не проверено» — честно не проверяли, и это не скрывается.

**Что нужно до начала:** подписка Claude (Pro/Max/Team) и Claude Code версии **не ниже 2.1.260**. Git нужен **только** на CLI-пути с git — на основном пути он не нужен. Все команды набираются в английской раскладке.

---

## Основной путь: Claude Desktop, без терминала (Д5)

**Проверено вживую 18.09.2026: работает целиком. Ноль диалогов разрешений. Перезапуск приложения не нужен — плагин появился сразу, даже в уже открытой сессии.**

### Шаг 1. Открыть настройки плагинов

В Claude Desktop открыть **Settings** → раздел **Plugins**.

Это тот же экран, который в проектных заметках назывался «Customize → Plugins» — и тот же, куда приложение приводит при попытке набрать `/plugin` в поле ввода (см. ниже про Д3). То есть промахнуться мимо него трудно: все дороги ведут сюда.

### Шаг 2. Добавить маркетплейс

Нажать кнопку **«Add ▾»** (с треугольником-стрелкой) → в выпавшем меню выбрать **«Add marketplace»** → затем **«Add from a repository»**.

Откроется поле для адреса репозитория. **Живая находка:** поле не пустое — оно предлагает **выпадающий список репозиториев вашего аккаунта GitHub**, если Desktop подключён к GitHub через Connectors. Курс лежит в репозитории `<владелец>/yunga`; выбрать его из списка или вписать HTTPS-адрес руками.

### Шаг 3. Sync

Нажать **Sync**. Маркетплейс **`kubrik`** регистрируется — запись появляется в `settings.json` (`source: git`). Никаких диалогов разрешений на этом шаге не возникает.

**Отдельно важно:** на этом пути **не нужны git credential helpers** — приложение обошлось без них (предположение §7.4 об их обязательности здесь опровергнуто; похоже, оно верно только для CLI-пути). Прогон шёл на **приватном** репозитории, потому что Desktop автора был подключён к GitHub через Connectors. **Для ученика репозиторий должен быть публичным** — у него такого подключения может не быть, а приватный источник без него не откроется.

### Шаг 4. Поставить сам плагин

В списке **Discover** найти плагин **`yunga`** → нажать **«Add»**.

### Шаг 5. Проверить, что встало

В поле ввода набрать `/` — в меню должны появиться команды **`/yunga:start`**, `/yunga:pomogi`, `/yunga:slovo`, `/yunga:pauza`, `/yunga:karta`, `/yunga:otkat`. Вместе с ними ставятся два служебных агента курса (`course-scout`, `course-checker`) — они работают сами, вызывать их не нужно.

Команды появляются **сразу**: ни перезапуска приложения, ни новой сессии не требуется (проверено).

### Шаг 6. Папка журнала — и первый запуск

Курс всегда запускается из своей папки, иначе каждое действие будет спрашивать разрешение отдельно.

1. Проводник → папка пользователя (`%USERPROFILE%`) → «Создать папку» → назвать её **`yunga-zhurnal`** (латиницей, без пробелов — так надёжнее в путях).
2. В Claude Desktop выбрать эту папку как **Project folder**.
3. В поле ввода набрать **`/yunga:start`**.

Дальше курс ведёт сам.

## Почему `/plugin` в поле ввода не работает (Д3)

Проверено 18.09.2026 — **как команда не работает**, и это не поломка вашей установки.

Если набрать в поле ввода `/plugin` или `/plugin marketplace add <адрес>`, приложение **не разбирает аргументы**: вместо выполнения команды оно просто открывает экран Settings → Customize → Plugins — тот самый, что описан выше в шаге 1. Ни ошибки, ни диалога, ни записи в `settings.json` при этом не появляется (проверено поиском по файлу).

Вывод для ученика: адрес репозитория в чат вставлять бесполезно, его негде «выполнить». Открывшийся экран — правильное место, просто продолжайте с шага 2 основного пути.

`/plugin` как настоящая команда есть **в CLI** — там она работает так, как описано ниже.

## Ветка: терминал (CLI) с git

Для тех, у кого уже установлены Claude Code CLI и git.

```
/plugin marketplace add https://github.com/<владелец>/yunga.git
/plugin install yunga@kubrik
```

Тонкости, о которых стоит знать заранее:

- **Только полный HTTPS-адрес.** Короткая форма `владелец/репо` клонируется по SSH (plugin-marketplaces.md:780) — без настроенных ключей не пройдёт. Обходной вариант, если короткая форма уже введена: переменная `CLAUDE_CODE_PLUGIN_PREFER_HTTPS=1` (env-vars.md:330).
- **Активацию Claude Code делает сам** (discover-plugins.md:192) — с версии 2.1.221 плагин включается сразу после установки.
- То же самое из обычного терминала, не из сессии: `claude plugin marketplace add …` (plugin-marketplaces.md:1239) и `claude plugin install yunga@kubrik`. Плагин подхватится при следующем запуске или по `/reload-plugins` (discover-plugins.md:303, :327).
- **Приватный репозиторий на этом пути требует настроенных git credential helpers** на машине ученика — выданный доступ к репозиторию их не заменяет (plugin-marketplaces.md:774-795). Хуже того, фоновая проверка обновлений helpers отключает и к приватному HTTPS-адресу не аутентифицируется (:784); страхуют `CLAUDE_CODE_PLUGIN_KEEP_MARKETPLACE_ON_FAILURE=1` (:790) и `gh auth setup-git` (:791). Публичный репозиторий снимает всю эту ветку целиком.

## Ветка: терминал (CLI) без git — archive

Работает с версии **2.1.224**, git и npm не нужны (plugin-marketplaces.md:264, :455). Маркетплейс добавляется по HTTPS-ссылке на файл `marketplace.json`, в котором у плагина указан `"source": "archive"`, `url` и `sha256` (:481-501).

Две оговорки:

- **Относительные пути в archive-маркетплейсе не работают** (:300) — только полные адреса.
- Имя маркетплейса и здесь **`kubrik`**, специально: способ установки в курсе один, и второй маркетплейс с тем же именем **заменяет** первый (:161). Если вы ставили курс одним способом, а потом добавляете другим — прежняя запись просто перезапишется.

## Запасной вариант: мост «терминал один раз, дальше Desktop» (Д4)

Нужен только в одном случае: **основной путь не прошёл**, а терминала на машине нет вовсе. Идея — поставить CLI одной вставкой, сделать им одну установку и больше к терминалу не возвращаться.

1. Открыть PowerShell и вставить одну строку (quickstart.md:39; без Git for Windows подходит именно PowerShell, :52):
   ```powershell
   irm https://claude.ai/install.ps1 | iex
   ```
2. В том же окне:
   ```
   claude plugin marketplace add <HTTPS-адрес репозитория или адрес marketplace.json>
   claude plugin install yunga@kubrik
   ```
3. Полностью закрыть Claude Desktop (значок в трее → Quit) и открыть заново.
4. Открыть папку журнала → `/yunga:start`.

Файл `settings.json` у приложения и CLI **общий** (desktop.md:876), поэтому установка из терминала видна и в приложении.

**Честно про этот путь:** он **не прогонялся** — на машине, где его писали, CLI уже стоял, и повторная установка ничего бы не доказала. Не подтверждено в том числе, появляется ли `claude` в PATH сразу в том же окне PowerShell. Поэтому Д4 и стоит последним: это страховка, а не рекомендация. Если он понадобился — об этом стоит сообщить в поддержку курса (`docs/SUPPORT.md`), это ценная информация.

## Slash-команды: что работает на какой поверхности

Проверено вживую в Desktop 18.09.2026. **Главный вывод: предсказать по документации нельзя** — правило «команды без аргументов в Desktop недоступны» опровергнуто (`/status` и `/usage` аргументов не имеют и работают, а `/memory` — тоже без аргументов — отказала). Настоящая граница проходит иначе: недоступны те команды, чья панель существует **только в терминале**.

| Команда | Desktop | CLI |
|---|---|---|
| `/status`, `/usage`, `/model`, `/mcp`, `/rewind`, `/resume` | работают, открывают свою панель | работают |
| `/context` | работает, отчёт приходит прямо в чат | работает |
| `/init`, `/fewer-permission-prompts` | есть как встроенные скиллы | есть |
| `/memory` | **недоступна** (`isn't available in this environment`) | работает |
| `/config`, `/doctor`, `/hooks`, `/permissions` | **недоступны** — это терминальные панели | работают |
| `/effort`, смена модели | меню приложения, не команда; `Shift+Tab` в Desktop нет | `/model`, `/effort`, `Shift+Tab` |
| `/skill-doctor`, `/deep-research` | [TODO: уточнить] — в списке скиллов сессии Desktop их не видно, но они могут быть клиентскими командами; вывод «недоступны» пока не делаем | есть |
| команды агентов (agent teams) | нет — только CLI | экспериментально |

Отсюда правило курса: **каждую команду маршрута проверяем на своей поверхности, а не выводим из документации**. И побочно, важное для проверок: отказ команды записывается в историю сессии, а успешно открытая панель — **нет**; значит «сработало» в Desktop подтверждается только глазами.

Плагин обновляется **только при смене номера версии** (plugin-marketplaces.md:70), а у сторонних маркетплейсов автообновление выключено (discover-plugins.md:485) — то есть само ничего не поменяется, пока вы не попросите.

## Удаление — и почему «удалить через UI» ≠ полный откат

Главное для ученика: **журнал остаётся цел в любом случае** — он лежит в домашней папке, а не внутри плагина.

- **CLI:** `claude plugin uninstall yunga@kubrik --keep-data` — флаг `--keep-data` сохраняет данные плагина (plugins-reference.md:1080, :1088).
- **Desktop:** Settings → Plugins → Manage plugins (удалить плагин), Manage marketplaces (убрать маркетплейс). В диалоге удаления **не соглашаться стирать данные**.

**Живая находка 18.09.2026, важная для тех, кто хочет вернуть машину ровно в исходное состояние.** Удаление через интерфейс Desktop чистит только кеш плагина и install-manifest. Состояние маркетплейса хранится **минимум в трёх местах**, и два из них после UI-удаления остаются:

| Где | Чистится через UI? |
|---|---|
| `settings.json` → `extraKnownMarketplaces` | **нет** — запись `kubrik` остаётся даже после полного перезапуска приложения |
| `~/.claude/plugins/known_marketplaces.json` | **нет** — отдельный файл, остаётся запись с адресом репозитория |
| `~/.claude/plugins/marketplaces/<имя>/` (клон репозитория на диске) | **нет** — папка остаётся; рядом могут накопиться временные папки `temp_git_*` от повторных попыток Sync |
| `~/.claude/plugins/cache/<маркетплейс>/` и `.install-manifests/` | да |

Поэтому полный откат — это отдельная работа, и делается она **по протоколу `consent.md`**: копия файлов в `backups/` → точечная правка `Edit` (удалить запись `kubrik` из двух json-файлов) → удаление папки-клона и временных папок → сверка. Курс не делает этого молча и по своей инициативе — только если ученик попросил вернуть всё как было.

Остаточные упоминания курса в `~/.claude.json` (счётчики `usageCount`/`lastUsedAt`) — инертная статистика: на поведение не влияет, трогать не нужно.

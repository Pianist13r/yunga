# Поверхности: чем приложение Claude Desktop отличается от терминала

Источник — DESIGN-v1.md §7.4 (последний абзац) и §7.5; живые итоги прогона на машине автора 18.09.2026 — `RELEASE-CHECKLIST.md`, «Этап 0.5». Это **справка**: пошаговые ветки установки и «куда нажимать» — в `procedures/surface-steps.md`.

**Поверхность** — это то, через что вы разговариваете с Claude Code: приложение Claude Desktop, окно терминала (CLI) или редактор кода. Основа курса — **Windows + Claude Desktop**; всё, что умеет только терминал, в курсе идёт веткой «если у тебя есть терминал» и никогда не бывает обязательным шагом.

## Что в Desktop устроено иначе

| Вещь | Как в терминале | Как в Desktop |
|---|---|---|
| Переключение режима разрешений | `Shift+Tab` по кругу | **`Shift+Tab` нет** — режим выбирается селектором в интерфейсе (DC\desktop.md:238-243) |
| Выбор модели и effort | команды `/model`, `/effort` | меню рядом с полем ввода (:238-240); `/model` в Desktop тоже открывает своё окно |
| Настройка разрешений | `/permissions` | **`/permissions` без аргументов не работает** (:920-921) — правила пишутся файлом настроек по протоколу `procedures/consent.md` |
| Настройки | `/config` | **текст после `/config` игнорируется** (:920-921): дописать настройку фразой нельзя, только файлом. По живой проверке 18.09.2026 в Desktop команда и вовсе отвечает «недоступна» |
| Команды агентов (agent teams) | есть, экспериментально | **только CLI** (:918) — в курсе это рассказ и демонстрация, не шаг |
| Расход контекста и лимитов | `/context`, `/usage` | то же самое плюс **кольцо** рядом с выбором модели: заполненность контекста и полосы лимитов плана (:247) |
| Список агентов | `/agents` | с версии 2.1.198 команда **только напоминает**, что агенты задаются файлами, и не открывает редактор (DC\commands.md:54) — смотреть надо файлы в `.claude/agents/` |
| Версия | `claude --version` | Help → About / Claude → About Claude (DC\desktop.md:931-932); версия встроенного Claude Code — `/status` |

## Главное правило про slash-команды

Все команды маршрута в Desktop проверяются **на живой поверхности**, а не выводятся из документации. Прогон 18.09.2026 показал, почему: правило из документации («команда без аргументов ответит „недоступна“») не подтвердилось — `/status` и `/usage` аргументов не имеют и прекрасно работают, а `/memory` — тоже без аргументов — отказала. Настоящая граница проходит иначе: **не работает то, чья панель существует только в терминале**.

Что известно точно по каждой команде — `reference/shortcuts.md`, колонка «Desktop».

Побочная мелочь того же прогона, полезная при разборе проблем: **отказ команды** («isn't available in this environment») попадает в запись сессии, а успешно открытая панель — нет. Значит, по истории разговора можно доказать, что команда не сработала, но нельзя доказать, что сработала: успех подтверждается только глазами.

## Установка и обновление плагина

Рабочий путь без терминала на Windows + Desktop подтверждён 18.09.2026: Settings → Plugins → «Add ▾» → «Add marketplace» → «Add from a repository» → Sync → «Add» на плагине. Ноль диалогов разрешений, перезапуск приложения не нужен, `/yunga:start` появляется сразу. Ввод `/plugin` и `/plugin marketplace add <адрес>` прямо в поле ввода Desktop **аргументы не разбирает** и просто открывает тот же самый экран настроек — это не ошибка, так устроено. Шаги с картинками — `procedures/surface-steps.md`.

**Удаление через интерфейс — не полный откат.** Состояние маркетплейса хранится минимум в трёх местах (`settings.json` → `extraKnownMarketplaces`, `~/.claude/plugins/known_marketplaces.json`, папка-клон `~/.claude/plugins/marketplaces/<имя>/`), а кнопка «удалить» чистит не все (проверено 18.09.2026). Если надо убрать курс начисто — это отдельный разговор с Claude, а не одна кнопка.

## Чего в Desktop нет совсем

- Плагинов внутри WSL (DC\desktop.md:439).
- Встроенного терминала до версии приложения v1.2581.0 (:180-185).
- Команд агентов (см. выше).

## Если поверхность другая

macOS и Linux в курсе идут как ветки: команды те же, отличается оболочка и вид путей — `reference/os-notes.md`. Ветки «CLI на Windows», «CLI на macOS», IDE и WSL на момент выпуска курса **не проверены живьём** (§10.2) — если вы работаете так, расхождения с текстом урока нормальны, и о них стоит написать в канал поддержки.

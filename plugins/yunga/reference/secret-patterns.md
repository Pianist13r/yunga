# Проверка на секреты без вывода значений

Источник — DESIGN-v1.md §5.1 (правила дословные), §5.2, §7.6 п.4 (это же проверяют evals курса). Файл — рабочая инструкция для Claude и для агентов `course-scout` / `course-checker`.

**Задача:** узнать, есть ли в файле секрет и где он, и при этом **ни разу не показать его значение** — ни ученику на экран, ни в запись сессии. Опасность неочевидна: поиск с показом строк (`content`) отдаёт строку целиком, а в JSON ключ и значение живут на одной строке — например, `headers` с токеном (DC\settings-reference.md:4273). То есть «я же искал только имя ключа» не спасает: на экран уедет и значение.

## Четыре правила

1. **Проход по списку паттернов (ниже) — только режимами `count` или `files_with_matches`.** Они отвечают «сколько совпадений» и «в каких файлах», без единой строки текста. Режим `content` без `-o` по секретным шаблонам — запрещён всегда, это отдельный пункт проверки курса (§7.6).
2. **Для `settings*.json` и `.mcp.json` номера строк добываются шаблоном *только ключа*** — `-n -o`: `-o` отдаёт не строку, а ровно совпавший кусок, то есть имя ключа и ничего больше. Отдельно ищутся блоки `env`, `headers` и любые `*Helper`.
3. **Границы блока** — от найденного ключа до закрывающей скобки **того же отступа**. Это и есть «опасная зона», внутрь которой обычным чтением не заходят.
4. **Обычный Read с `offset`/`limit`** — только **вне** таких блоков. Поле `env` разбирается по именам переменных: «там задан `MOSTAI_MAX_PRICE`» — можно, значение — нельзя.

Читать эти файлы целиком (Read без `offset`/`limit`) нельзя вообще — §5.1. Файлы из `reference/never-open.md` не открываются даже так.

## Что ищем (список паттернов)

Регулярки одинаковы на всех системах — их исполняет сам инструмент поиска Claude Code, а не оболочка.

| Что ловим | Шаблон |
|---|---|
| Имена «говорящих» ключей | `(?i)(api[_-]?key\|secret\|password\|passwd\|token\|cookie\|credential)` |
| Заголовок закрытого ключа | `-----BEGIN [A-Z ]*PRIVATE KEY-----` |
| Ключи сервисов вида `sk-…` / `pk-…` | `(?i)\b(sk\|pk)-[A-Za-z0-9_-]{16,}` |
| Заголовок авторизации | `(?i)"?authorization"?\s*[:=]\s*"?(bearer\|basic)` |
| Любое длинное «слово без смысла» (шумный шаблон, только как последний проход) | `[A-Za-z0-9_\-]{40,}` |
| Имя ключа в JSON — **для номеров строк, с `-n -o`** | `"[A-Za-z0-9_]+"\s*:` |
| Опасные блоки в настройках — **с `-n -o`** | `"(env\|headers\|[A-Za-z]*Helper)"\s*:` |

Последний шаблон шумит (под него попадают хэши, длинные пути, id) — поэтому он идёт в режиме `count` и его результат сам по себе ничего не доказывает, это повод посмотреть на имена ключей рядом.

## Примеры: три правильных вызова

**1. Есть ли вообще секреты в папке проекта** — считаем, не показываем:

```
Grep(pattern="(?i)(api[_-]?key|secret|password|token|cookie|credential)",
     path="C:/Users/…/moy-proekt", output_mode="count")
```

**2. Где в `settings.json` лежат опасные блоки** — только имена ключей и номера строк:

```
Grep(pattern="\"(env|headers|[A-Za-z]*Helper)\"\\s*:",
     path="C:/Users/…/.claude/settings.json", output_mode="content", -n=true, -o=true)
```

Ответ выглядит как `41:"env":` — то есть блок начинается на 41-й строке. Дальше читаем **только** то, что лежит вне него.

**3. Извлечь безопасную часть настроек** — чтение кусками мимо блоков:

```
Read(file_path="C:/Users/…/.claude/settings.json", offset=1, limit=38)
```

Частичное чтение с явными `offset`/`limit` — полноценное: Claude Code засчитывает его и разрешает после него правку файла (проверено на машине автора 18.09.2026, прогон P5 — `RELEASE-CHECKLIST.md`; прогноз по документации не подтвердился).

## Если инструмента поиска нет — в хуке или в скрипте

Хуки пишутся на оболочке, а она разная (§7.3). Там те же паттерны, но вызов свой, и обе формы **обязаны считать, а не печатать**:

- **Git Bash / macOS (`sh`):** `grep -rciE '(api[_-]?key|secret|password|token|cookie)' "$HOME/proekt"` — `-c` считает, `-i` без учёта регистра, `-r` по папке. Если нужен кусок совпадения, а не строка, — `grep -oE`, никогда голый `grep`.
- **Windows, PowerShell 5.1:** `(Select-String -Path "$HOME\proekt\*" -Pattern 'api[_-]?key|secret|password|token|cookie' | Measure-Object).Count` — важно именно завершающий `Measure-Object`: сам `Select-String` по умолчанию печатает найденную строку целиком, то есть ровно то, чего нельзя. Регистр он и так не учитывает.
- Разбор JSON в хуках без сторонних программ: `sh` — `grep -o`, PowerShell — `ConvertFrom-Json` (§7.3).

## Итог одной фразой

Секрет ищем как **место**: файл, ключ, номер строки. Как только в ответе инструмента может появиться значение — вызов сделан неправильно, и его надо переписать, а не «просто не смотреть».

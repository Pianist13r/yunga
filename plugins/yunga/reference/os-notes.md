# Особенности систем: Windows, Git Bash, macOS

Источник — спецификация курса, §7.2, §7.3, §5.1. Курс написан под **Windows**, поэтому здесь собрано то, из-за чего одна и та же команда ведёт себя по-разному. Читать целиком не надо — заглядывайте, когда что-то не сработало «как в уроке».

**Оболочка** — программа, которая исполняет команды. На Windows их обычно две: **PowerShell** (стоит всегда) и **Git Bash** (появляется вместе с Git for Windows, понимает команды как на macOS/Linux). На macOS и Linux — `sh`/`bash`.

## Windows, PowerShell 5.1

Это версия PowerShell, встроенная в Windows «из коробки». Две вещи ломаются в ней регулярно:

1. **Кириллица в хуках.** Текст с русскими буквами выходит крякозябрами, пока в начале скрипта не задана кодировка:
   ```powershell
   [Console]::OutputEncoding = [Text.Encoding]::UTF8
   ```
2. **JSON для хука — только в одну строку.** Claude Code читает ответ хука как JSON; `ConvertTo-Json` по умолчанию форматирует его в несколько строк, и ответ не разбирается. Нужен ключ `-Compress`:
   ```powershell
   @{ systemMessage = "Проверь сумму перед запуском" } | ConvertTo-Json -Compress
   ```

Обе поправки — обязательная часть шаблонов хуков M12 (§7.3). Разбор JSON, который пришёл хуку на вход, в PowerShell делается через `ConvertFrom-Json` — сторонние программы (`jq`, Python, Node) курс не требует.

Ещё две мелочи PowerShell, которые встретятся в M13:
- переменная вида `$env:ИМЯ = "1"` живёт до закрытия окна, а не до конца команды; убрать — `Remove-Item Env:ИМЯ` или просто закрыть окно;
- пути пишутся с обратными слешами (`C:\Users\...`), но Claude Code одинаково понимает и прямые (`C:/Users/...`) — в настройках удобнее прямые, они не требуют экранирования.

## Git Bash на Windows — и что без него ломается

Git Bash ставится вместе с Git и даёт на Windows привычные `grep`, `sed`, `cp`. Курс его **не требует**, но одна вещь без него падает жёстко:

> **Скилл с `shell: bash` без Git Bash не работает** (DC\skills.md:646). Речь про скиллы, которые подставляют результат команды прямо в свой текст — так называемые `` !`команды` ``.

Поэтому в самом курсе таких скиллов нет вообще (§7.2): плагин `yunga` не содержит ни одной подставляемой команды, чтобы одинаково работать и с Git Bash, и без него. Если вы встретите чужой скилл, который на Windows молча не срабатывает, — это первое, что стоит проверить.

## Как курс различает оболочки в хуках

У хука есть поле `shell`, и оно решает, кто исполняет команду (DC\hooks.md:462, :472): `sh -c`, Git Bash или PowerShell. Практика курса (§7.3):

- каждый хук M12 даётся **в двух вариантах** — для `sh` и с `"shell": "powershell"`;
- сторожа команд ловят сразу обе формы: `Bash|PowerShell` (DC\tools-reference.md:397), потому что на Windows команду может выполнить как одна, так и другая;
- проверка секретов в хуке: `sh` — `grep -o`, PowerShell — `Select-String` строго со счётом, детали и примеры — `reference/secret-patterns.md`.

Диагностика курса тоже двуликая: на Windows без Git Bash она идёт через PowerShell (DC\tools-reference.md:391), и `procedures/diagnose.md` хранит обе формы.

## macOS — коротко

- Оболочка обычная (`zsh`/`bash`), команды из «бэш-варианта» подходят без изменений; отдельная настройка кодировки не нужна.
- Пути — через прямой слеш и без буквы диска: `~/yunga-zhurnal/` вместо `C:\Users\Имя\yunga-zhurnal\`.
- При первом вызове `git` система может сама предложить установить инструменты разработчика — можно согласиться, а можно выбрать путь установки курса без git (§7.4); это поведение macOS, а не Claude Code.
- Меню приложения: «Claude → About Claude» вместо «Help → About».

Ветка macOS в курсе **живьём не проверялась** (§10.2) — оба участника финального тестирования на Windows. Расхождения возможны.

## Что одинаково везде

Инструменты самого Claude Code — чтение файлов, поиск, правка — от системы не зависят: одинаковый поиск, одинаковые регулярки, одинаковые правила разрешений. Отличается ровно то, что уходит в оболочку: команды, хуки и пути.

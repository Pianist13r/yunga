# Судовой журнал ученика — устройство и контракт `schema 1`

Источник — DESIGN-v1.md §6.1–6.3, §4.7. Единый владелец формата: этот файл. Скиллы `start`, `pauza`, `karta`, `otkat` и кондуктор шага (`procedures/gate.md`) читают и пишут журнал **только так, как описано здесь**; расходится код и этот файл — правда на стороне этого файла.

## Где журнал и почему именно там

`~/yunga-zhurnal/` — домашняя папка ученика, латиница без пробелов. Три причины: путь без кавычек в shell и JSON; домашняя папка есть на любой ОС; лежит **вне** `~/.claude`, поэтому не удаляется вместе с плагином и не попадает под защищённый путь.

Курс всегда запускается **из этой папки** (Desktop — она выбрана как Project folder, CLI — `claude` запущен в ней): тогда записи в журнал идут без каскада диалогов разрешений.

## Структура

```
yunga-zhurnal/
├── README.md        # зачем эта папка — первое, что откроет ученик через полгода
├── progress.md      # ГДЕ Я СЕЙЧАС: schema, версия, поверхность, текущий шаг, гейты
├── profile.md       # кто ученик, оси, 3 сильные / 3 риска / флаги, его проекты (≤4 КБ)
├── plan.md          # 3 следующих шага, таблица модулей, история пересчётов
├── decisions.md     # решения по устройству системы (переносятся на выпуске, не архивируются)
├── changes.md       # CH-NNN: что менялось ВНЕ журнала и как это вернуть
├── passport.md      # «что у меня стоит»: паспорт каждой включённой вещи
├── inbox.md         # мысли на потом, вопросы к следующему разу
├── capsule.md       # закладка курса ≤2 КБ — где остановились
├── journal/         # дневник занятий: по файлу на встречу
├── pesochnica/      # ТОЛЬКО учебные и разрушительные проверки, только на файлах Claude
├── Архив/           # сюда переезжает отработавшее; курс ничего не удаляет
├── backups/         # копии перед каждой правкой + manifest.md в каждой папке
└── .gitignore       # backups/
```

Папки `journal/`, `pesochnica/`, `Архив/`, `backups/` создаются в момент первой надобности, не заранее.

## `progress.md` — контракт `schema 1`

Frontmatter — машинная часть, её читает `start`. Тело — человеческая, её читает ученик и показывает `karta`.

```yaml
---
schema: 1
plugin_version: 0.1.0      # версия плагина, которая завела журнал
claude_version: 2.1.273    # версия Claude Code на последнем занятии
surface: desktop           # desktop | cli
os: windows                # windows | macos | linux
tz: UTC+5                  # часовой пояс ученика — все даты в журнале с ним
stage: 1                   # 1 «Юнга» | 2 «Матрос» | 3 «Штурман»
current:
  module: M01              # ID из reference/module-ids.md
  step: 2                  # номер шага внутри модуля, 1–3
last_seen: 2026-09-18 14:30 UTC+5   # конец последнего занятия — по нему считается пауза
проходил: ученик           # ученик | автор (прогон автора, DESIGN-v1 §4.7)
---
```

Все поля обязательны, кроме `claude_version` (появляется после первой диагностики). Пустых значений нет: не знаем — спрашиваем ученика, а не пишем заглушку.

**Тело файла — таблица гейтов**, по строке на модуль:

```
| Модуль | Статус | Улика | Дата |
|---|---|---|---|
| M00 Старт | пройден | backups/2026-09-18_start/manifest.md | 2026-09-18 UTC+5 |
| M01 Основы сессии | идёт | — | — |
```

Статусы — ровно пять, других не бывает: `не начат` · `идёт` · `пройден` · `отложен` · `недоступно (версия ниже N)`.
Ниже таблицы — раздел «Вехи»: «деньги под замком» (после M03), мини-выпуск 1 (после M07), мини-выпуск 2 (после M11), выпуск (M15) — с датой или прочерком.

**Когда пишется:** `current` и строка гейта — **сразу после шага**, не в конце сессии (`procedures/gate.md`). `last_seen` — в `pauza` и в конце любой сессии курса.

## Где ученик находится — `home.json`

В каталоге данных плагина (`~/.claude/plugins/data/yunga-kubrik/`) лежит единственный файл:

```json
{"schema": 1, "workbook_path": "C:\Users\<имя>\yunga-zhurnal"}
```

Он нужен, чтобы `start` нашёл журнал, даже если сессия запущена из другой папки. Каталог данных удаляется вместе с плагином — это нормально и не потеря: при пропаже `home.json` `start` сначала проверяет `~/yunga-zhurnal/`, и только если её нет — спрашивает путь у ученика. **Журнал первичен, `home.json` — просто указатель.**

## Кто чему владелец

| Что записываем | Куда | Почему не в журнал |
|---|---|---|
| Прогресс, гейты, план, закладка курса, дневник, `changes.md`, бэкапы | журнал | — |
| Факты о проектах ученика, «запомни, что…» | авто-память / `MEMORY.md` | журнал сворачивается на выпуске, факты должны пережить курс |
| Правила поведения, карта «где что лежит» | `CLAUDE.md` ученика и проектов (M05) | то же |
| Решения по устройству системы | `decisions.md` → на выпуске в карту и `CLAUDE.md` | остаются работать после курса |
| Капсула рабочей задачи | файл в проекте по шаблону M07 | это не про курс, это про его работу |

Правило роутера на «запомни»: про проект → память; про курс → журнал; **сомневаешься — спроси ученика**, не решай за него.

## Мелочи, у которых тоже должен быть один дом

Чтобы скиллы не разошлись в трактовках:

- **Домашка** («попробуй до следующего раза») — строкой с датой в `inbox.md`, а из закладки на неё ссылаются в разделе «СЛЕДУЮЩИЙ ШАГ». Отдельного файла у домашки нет, и она необязательна: нет естественного задания — не выдумываем.
- **Замеры расхода** (процент контекста из `/context`, состояние полос из `/usage`) — строкой в файл занятия `journal/<дата>.md`. В закладку они не идут: у неё бюджет 2 КБ и фиксированные семь разделов.
- **Дата и время** берутся у системы, а не по памяти, и всегда с часовым поясом из поля `tz`.

## Несовпадение `schema` — миграций нет, это сознательно

`start` прочитал `schema`, а она не 1 — курс **не чинит журнал молча**. Он говорит ученику: «журнал старого формата», показывает ручную инструкцию из `CHANGELOG.md` плагина (бэкап → перечень изменений → `changes.md`) и **ждёт «да»** по `procedures/consent.md`. Автоматическая миграция запрещена: журнал — файлы ученика, и правит их курс только по протоколу.

## Свёртка на выпуске (M15)

Остаются на месте: `profile.md`, `changes.md`, `passport.md`, `decisions.md`, `backups/`. Уезжают в `Архив/`: уроки, закладки, дневник. **Ничего не удаляется** — «убрать» в курсе всегда означает «переместить».

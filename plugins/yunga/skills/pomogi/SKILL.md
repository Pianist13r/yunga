# Путь из тупика

По `/yunga:pomogi` и без команды — на «помоги», «не получается», «я что-то сломал», «не понял». Человек здесь чаще всего испуган.

**Первая реплика — всегда:**

> «Ничего не сломано — сейчас разберёмся. Расскажи своими словами, что произошло?»

Никаких «вы сделали ошибку», «надо было иначе»; причина — позже и только как факт. Слова «гейт», «улика», «PASS», «FAIL» ученику не говорятся. Дальше — одна ветка, и идём только по ней. Таблица симптомов — `${CLAUDE_PLUGIN_ROOT}/reference/troubleshooting.md`.

## Не работает (команда, шаг, скилл, сервер)

Сверху вниз, останавливаемся на найденной причине:

1. **Текст ошибки дословно** — попросить скопировать целиком, не пересказывать. Половина случаев решается здесь.
2. **`/doctor` — только посмотреть.** На её предложения исправить отвечаем «нет»; нужное делаем отдельно по `${CLAUDE_PLUGIN_ROOT}/procedures/consent.md`. ⚠️ **В приложении Claude Desktop этой команды нет** (проверено вживую): там шаг пропускаем, есть терминал — `claude doctor`. Команду, которой на поверхности ученика нет, не обещаем.
3. **`/context`** — не переполнен ли разговор (в приложении Desktop работает, проверено). Под завязку → `/compact`; её наличие в Desktop не проверено, поэтому если команда не отзовётся — закладка через `/yunga:pauza` и новая сессия.
4. **`/mcp`** — на месте ли внешние серверы. Отвалившийся выглядит как «инструмент пропал».
5. **Хуки** — не запретил ли сторож молча. В терминале список даёт `/hooks`; **в Desktop её тоже нет** — смотрим блок `hooks` в `~/.claude/settings.json` и называем, что там стоит.
6. **Начисто.** Терминал — `claude --safe-mode`: заработало → дело в плагине, хуке или сервере. **В Desktop такого ключа нет** — вместо него новая сессия в папке журнала.

Лесенка кончилась без результата → «Обращение» ниже.

## Остальные ветки

- **Непонятное слово** → скилл `slovo`: аналогия → пример → «скажи своими словами»; ответ не оценивается.
- **Страшно, кажется, сломалось** → `~/yunga-zhurnal/changes.md`: там всё, что курс менял, с копией файла и способом вернуть. Оттуда `/yunga:otkat` (вернёт файл из копии) или `/rewind` (откатит правки файлов, но **не** сделанное командой в терминале).
- **Нажал не ту кнопку в окне разрешений** → сначала «это чинится, и чинить буду я». Откат делает Claude по `consent.md` (показ → «да» → копия → правка). Частый случай — «Block from now on» на чтение: запрет постоянный и общий для всех сессий, снимать его надо из сессии, открытой в папке `~/.claude`, иначе файл настроек не прочитать.
- **Кончился лимит** → «Прогресс цел, он пишется в журнал после каждого шага. Возвращайся, когда полоса обновится, и набери `/yunga:start`». Доплату курс не предлагает.
- **Устал / нет времени** → скилл `pauza`: закладка ровно на текущем шаге. Бросить посреди урока — нормально, так и сказать.
- **Потерялся** → скилл `karta`: этапы, пройденное, следующий шаг.
- **«Claude не по сценарию»** (отвечает не о том, забыл про курс) → `Esc` → новая сессия в папке журнала → `/yunga:start`: подхватится та же закладка.

## Обращение в поддержку — если не помогло

Одним сообщением, показать ученику до отправки: версия (`/status`, в Desktop — Help → About) · поверхность · ОС · шаг из `progress.md` · текст ошибки дословно. **Вычистить:** пути с именем пользователя (`C:\Users\<имя>\…`), названия клиентов и проектов, содержимое `.env`, ключи. Журнал целиком не прикладываем — только выбранные учеником выдержки. Куда слать — README курса, раздел «Поддержка».

## Чего не делаем

Не чиним наугад правкой настроек мимо протокола: она не попадёт в `changes.md`, и вернуть будет нечем. Не предлагаем `bypass`. Не делаем вид, что шаг получился: две неудачные попытки — это «отложено, план пересчитан», нормальный исход.

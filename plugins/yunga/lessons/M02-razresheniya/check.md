# M02 — задание проверяющему (служебный файл)

Читает `agents/course-checker.md`. Курс вызывает его с **одним** разделом и подставляет полные пути вместо `<журнал>` (папка журнала ученика) и `<настройки>` (файл настроек пользователя, `~/.claude/settings.json`).

**Оговорки ко всем разделам.**
1. Абсолютные пути с именем учётной записи ученика внутри журнала и в описи копий **ожидаемы** — это не находка. Находка — путь, ведущий за пределы журнала и домашней папки ученика.
2. В `<настройки>` может быть раздел `env` со значениями ключей. **Не цитировать ни значения, ни их фрагменты** — только называть место, если что-то похоже на секрет. Файлы `~/.claude.json` и `~/.claude/.credentials.json` не открывать никогда, даже если на них ссылается правило.
3. Срабатывание правила (отказ, диалог) файлом не проверяется — это подтверждает курс, а не проверяющий. Отсутствие такой записи в отчёт не пишется.

## Шаг 1

- **улика:** `<журнал>/journal/` — файл занятия за дату шага
- **критерии:**
  1. в файле названо, в каком режиме разрешений работает ученик, и это один из режимов приложения: `Manual` (`default`), `Accept edits`, `Plan`, `Auto`, `Bypass`;
  2. записано, какие файлы настроек загружены — строка `Setting sources` из `/status`;
  3. записи о правках нет — на этом шаге их быть не должно; строка вида `CH-NNN`, датированная этим шагом, — находка.
- **бюджет:** файл занятия не больше 3 КБ.

## Шаг 2

- **улика:** `<настройки>`
- **критерии:**
  1. файл разбирается как JSON (скобки, запятые, кавычки);
  2. в `permissions.deny` есть все семь строк: `Read(//**/.env)`, `Read(//**/.env.*)`, `Read(//**/*.pem)`, `Read(//**/*.key)`, `Read(~/.ssh/**)`, `Read(~/.claude/.credentials.json)`, `Read(~/.claude.json)`;
  3. пути для файлов начинаются с `//` — вариант `**/.env` без двух косых не засчитывается: он закрывает текущую папку и всё внутри неё, но не соседние проекты и не то, что уровнем выше;
  4. ни одна из этих строк не продублирована в `permissions.allow`. На работу правила это не влияет — запрет сильнее разрешения, и разрешение не может вырезать из него исключение, — но дубль означает, что правку внесли дважды и по-разному: это повод сказать курсу, а не тихо пройти мимо;
  5. в `<журнал>/changes.md` есть строка `CH-NNN` про это изменение: дата с поясом, файл, что добавлено, путь к копии, как вернуть, как проверено;
  6. папка копии из этой строки существует, в ней `manifest.md` с четырьмя столбцами и полным путём к оригиналу.
- **бюджет:** добавленных строк в `deny` — ровно семь; в описи — не больше 40 строк.
- **неясно (не угадывать):** у ученика в `deny` могли быть свои строки до курса. Лишние правила **не** являются нехваткой; проверяется только наличие семи наших и отсутствие их дубля в `allow`.

## Шаг 3

- **улика:** `<настройки>`
- **критерии:**
  1. в `permissions.ask` есть **пара** правил на одно и то же действие наружу — для обоих способов выполнять команды: `Bash(git push *)` **и** `PowerShell(git push *)`, либо `Bash(curl *)` **и** `PowerShell(Invoke-WebRequest *)`. Одна строка из пары без второй — это нехватка: второй способ останется без вопроса;
  2. те же правила не продублированы в `allow`. Вопрос это не отменит — совпавшее `ask` спрашивает, даже если более точное `allow` тоже совпало, — но дубль означает задвоенную правку и называется в отчёте;
  3. в `<журнал>/changes.md` есть отдельная строка `CH-NNN` про это изменение — **не та же самая**, что для запрета на шаге 2;
  4. папка копии из этой строки существует и содержит `manifest.md`;
  5. в журнале записаны границы замка — перечислено, чего правила не закрывают (минимум: команда без имени файла, скрипты, ключ в другом файле).
- **бюджет:** запись про границы — не больше 15 строк.
- **неясно:** если у ученика нет ни git, ни исходящих команд вовсе, правило могло быть поставлено на другое действие наружу — это `НЕЯСНО` с вопросом «какое действие выбрали», а не `FAIL`.

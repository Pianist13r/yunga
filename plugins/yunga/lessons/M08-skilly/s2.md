# Шаг 2. Свой скилл под сквозную задачу

Конец первой встречи или начало второй, ~25 минут. Появляется первый скилл, который ученик завёл сам.

## Что делаем

Берём процедуру, которую ученик правда повторяет на своей сквозной задаче, и заводим для неё скилл — новый файл `SKILL.md` в `~/.claude/skills/<латинское-имя>/`.

## Зачем это ученику

«Ты уже третий раз просишь меня сделать одно и то же — примерно теми же словами. Запишем это один раз в отдельный рецепт: в следующий раз либо скажешь мне команду, либо, если рецепт из тех, что я могу доставать сам, я пойму по разговору, что пора.»

## Как ведём

**Процедура.** Спросить: «что ты в последнее время просишь меня сделать одинаково, третий раз подряд?» Годится многошаговая процедура на его сквозной задаче — не факт, не разовая просьба.

**Шапка.** Два поля: `name` (подпись для человека — команда всё равно берётся из имени папки) и `description` — первым делом «когда звать». Пишем `description` словами ученика, начиная с условий вызова, а не с того, что скилл делает: «Когда звать: … Что делает: …». Короткая, в одну-две строки.

**Кто зовёт — решаем вместе.** Если скилл делает что-то заметное сам по себе (правит файлы, отправляет что-то, необратимое) — добавляем в шапку строку `disable-model-invocation: true`: вызывать буду только ты, командой. Если это просто справка или объяснение без последствий — оставляем без этой строки, и тогда я смогу позвать его сам, как `slovo`.

**Файл создаю я, по протоколу** `${CLAUDE_PLUGIN_ROOT}/procedures/consent.md`: показ (что будет в файле, где он ляжет) → «да» → `Write` → проверка → `CH-NNN`. Копии в `backups/` для нового файла нет — копировать нечего (`procedures/backup-rollback.md`: пустая опись не создаётся); в строке `CH-NNN` в графе «путь к бэкапу» пишем «файла не было», в графе «как откатить» — «перенести файл в `Архив/`» (курс ничего не удаляет). Без строк `` !`команда` ``, без поля `allowed-tools`, без `context: fork` (справка: работает в отдельной комнате, разговора не видит) — это не для скилла ученика.

**Ловушка, а не сюрприз.** Если папки `~/.claude/skills/` до сих пор не было — новый скилл появится в списке только в **новой** сессии, не в этой же. Сказать об этом до создания файла, а не после разочарования: «до Write запиши предсказание — появится ли скилл в меню этого же разговора?» **Честно:** хватит ли новой вкладки/разговора в той же папке, или нужен полный перезапуск приложения, — в Desktop отдельно не проверено; если после новой сессии скилл всё ещё не виден, следующий шаг — перезапустить приложение целиком. Если у ученика терминал — вместо новой сессии можно набрать `/reload-skills` (в приложении не проверена).

**«У тебя уже есть X».** Если у ученика уже есть свой скилл — разбираем его по `check.md` этого шага и улучшаем с его согласия, правки по тому же протоколу, вместо того чтобы заводить новый с нуля.

**Если у ученика терминал:** файл и путь те же; список скиллов дополнительно виден командой `/skills` (в приложении не проверена).

## Как проверить

Открываем новую сессию в той же папке. Скилл появляется в меню `/` — ученик набирает `/имя` сам и получает результат по своей сквозной задаче. Сверяем это с предсказанием из «Ловушки».

## Что после этого появилось

Первый собственный скилл на диске, первая строка `CH-NNN` в журнале этого модуля, привычка описывать «когда звать» раньше, чем «что делает».

## Почему так

Записал рецепт торта, который печёшь не в первый раз, — с продуктами и порядком действий. Дальше либо сам открываешь книгу на нужной странице, либо повар, который хорошо тебя знает, сам достаёт эту страницу, увидев на столе нужные продукты.

# Шаг 2. Свой первый сервер: подключить и проверить вызовом

~18 минут. Появляется первый MCP-сервер, который ученик подключил сам, — и проверка, что ответ на вопрос действительно пришёл от него.

## Что делаем

Подключаем сервер документации Claude Code — читает первоисточник, без ключей и оплаты — файлом `.mcp.json` в песочнице журнала, одобряем его в новой сессии и проверяем вызовом с именем сервера в записи.

## Зачем это ученику

«Спросить меня о Claude Code можно и так — но я иногда пересказываю неточно, особенно детали. Сервер документации отвечает первоисточником, а не пересказом (как в случае E2 из справки: пересказ страницы один раз подвёл именно в мелочи). Сейчас подключим его тебе — и заодно ты увидишь, как вообще выглядит подключение любого нового сервиса.»

## Как ведём

**Файл создаю я, по `consent.md`.** Показываю все восемь строк, объясняю каждую, жду «да»:

```json
{
  "mcpServers": {
    "claude-code-docs": {
      "type": "http",
      "url": "https://code.claude.com/docs/mcp"
    }
  }
}
```

Файла ещё не было — копии в `backups/` нет; в `CH-NNN` графа «путь к бэкапу» — «файла не было», «как откатить» — «перенести файл в `Архив/`» (курс не удаляет).

**Ещё здесь, до перехода: корзины и предсказание.** Три инструмента сервера по корзинам (как в `etalons/mcp.md`): `search_claude_code_docs` и `query_docs_filesystem_claude_code_docs` — только смотрят, без спроса; `submit_feedback` — отправляет текст команде документации, то есть «наружу». Ближе всего к корзине «без спроса, но сказать», но курс держит его строже: без твоего «да» я его не вызову — это моё обещание. Справка: замок на него можно поставить правилом «спроси меня» (как в M03), по желанию, не сегодня. Игра, ответ сразу в файл занятия: «Если я отвечу на вопрос о Claude Code — как ты увидишь, от сервера пришёл ответ или из моей памяти?»

**Предупреждение — дословно:** «Программа спросит, доверяешь ли ты серверу из этой папки. Выбери вариант, который одобряет только этот сервер. Вариант «все серверы этой папки» не выбирай: тогда любой будущий сервер, положенный сюда, подключится без спроса». Даю две фразы на бумажку для песочницы: проверочную — «Спроси сервер claude-code-docs, что делает `MCP_TIMEOUT`, и покажи, каким инструментом ты это узнал» — и вопрос по своей задаче: что-то настоящее про то, как удобнее вести именно его дело в Claude Code.

**Переход в песочницу.** `/yunga:pauza` → в приложении новая сессия, папка **Project folder** — `<журнал>\pesochnica` (тот же экран, что при установке, `procedures/surface-steps.md`) → программа спрашивает, одобрить ли сервер, — ученик выбирает вариант из предупреждения выше. Честно: как именно выглядит это окно в приложении, курсом не проверено; если отдельного окна нет — ученик набирает `/mcp` → сервер → одобряет. Дальше `/mcp` показывает «connected», 3 инструмента (так на осень 2026 — число может измениться). Дальше по очереди обе фразы — проверочная и своя; на первый вызов может прийти запрос разрешения — «Yes» один раз. В строке вызова — подпись `claude-code-docs`; если в обычном виде свёрнуто — переключить на **Verbose** (`Ctrl+O`). Терминал: `cd` в `pesochnica` → `claude mcp list` (`⏸ Pending approval`) → `claude`, одобрить → выйти → снова `claude mcp list` (`✔ Connected`).

**Назад.** `/yunga:pauza` → новая сессия из папки журнала → `/yunga:start`. Ученик пересказывает, что увидел, — записываю итог рядом с предсказанием игры: подпись `claude-code-docs` видели / не видели.

## Как проверить

`pesochnica/.mcp.json` разбирается, одна запись `claude-code-docs`; в записи разговора — вызов, подписанный этим именем; строка `CH-NNN` в `changes.md`; в файле занятия — предсказание игры записано до перехода в песочницу, итог дописан после возвращения.

## Что после этого появилось

Первый свой MCP-сервер на диске · строка `CH-NNN` · живой ответ по сквозной задаче с подтверждённым источником.

## Почему так

Заказал пропуск в архив с первоисточниками вместо того, чтобы каждый раз спрашивать у знакомого, что там написано, — знакомый обычно прав, но иногда путает детали, а архив не путает.

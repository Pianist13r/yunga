# M10 — что засчитывает модуль

Процедура целиком — `${CLAUDE_PLUGIN_ROOT}/procedures/gate.md`. Ученику служебные слова не звучат: «готово» или «не хватает вот этого — чиним вместе».

## Особенность этого модуля

`s1` — только глазами и записью в дневнике, файла-результата там не появляется. `s2` даёт главную файловую улику модуля (`.mcp.json`), но подтверждение «ответ пришёл от сервера» видно только в моменте — по подписи в строке вызова. `s3` — паспорт и игра scope.

| Шаг | Файлом | Глазами |
|---|---|---|
| `s1` | запись в файле занятия: серверы из `/mcp`, «чей» каждый, Connectors | ученик сам открыл `/mcp` и `+ → Connectors` |
| `s2` | `pesochnica/.mcp.json`, строка `CH-NNN`, нет `enableAllProjectMcpServers: true` в `settings.local.json` | одобрение, «connected» с 3 инструментами, строка вызова с именем `claude-code-docs` |
| `s3` | строка в `passport.md` со всеми четырьмя частями; если убрали — `CH-NNN` на перенос | `/mcp` в сессии журнала сервера не показывает (у кого `claude-code-docs` уже был «мой везде» — виден, и это тоже ожидаемо) |

## Игра «предскажи → проверь»

**На `s2`, до вызова:** «Если я отвечу на вопрос о Claude Code — как ты увидишь, что ответ пришёл от сервера, а не из моей памяти?» Записать ответ, потом посмотреть на подпись `claude-code-docs` в строке вызова (Verbose, `Ctrl+O`, если в обычном виде свёрнуто).

**На `s3`, гейт модуля.** «В сессии курса — папке журнала — сервер `claude-code-docs` будет?» Записать предсказание **до** проверки, затем `/mcp` прямо в сессии журнала. Ожидание по документации: нет.

## Если улики нет

Две честные попытки — и выбор: `/yunga:pomogi` или «отложено, план пересчитан». Отложенный M10 не закрывает M11 (он зависит от M04 и M08, не от M10) и не блокирует мини-выпуск 2 — тот просто снимает свою проверку MCP и отмечает это в журнале.

Частые причины:
- сессия проверки открыта не в песочнице, а в журнале или где-то ещё — `.mcp.json` читается из той папки, где реально лежит файл;
- одобрение сервера было отклонено — он записан в отказ; сбросить можно терминальной командой `claude mcp reset-project-choices`, иначе Claude правит `pesochnica/.claude/settings.local.json` по `consent.md`;
- ошибка в JSON — Claude Code такую запись молча пропускает, сервер просто не появляется;
- файл `.mcp.json` правили в этой же сессии — нужна **новая** сессия, он читается только при старте;
- сеть не пускает к `code.claude.com` (например, рабочий компьютер за корпоративным фильтром) — это не вина ученика, отложить шаг честно;
- подпись сервера в строке вызова свёрнута в обычном виде — переключить на **Verbose** (`Ctrl+O`);
- журнал ученика лежит внутри git-репозитория — тогда корнем проекта для сессии в `pesochnica` может оказаться корень репозитория, и `.mcp.json` из подпапки может не прочитаться (в документации прямо не описано, курсом не проверено) — отложить честно и записать;
- во второй и следующий раз `/mcp` показывает у сервера статус `cached` вместо `connected` — это нормально, сервер подключится при первом вызове инструмента.

## Чего здесь не требуем

Не требуем своего сервера, кроме учебного. Не требуем терминала — все шаги проходятся в приложении, терминал только веткой. Не требуем ask-правила на `submit_feedback` — это справка по желанию, не часть гейта. Не требуем настройки Connectors из чата — в `s1` их достаточно увидеть и назвать. Не требуем `claude mcp add --scope user` или правки `~/.claude.json` — курс этот файл не открывает и не проверяет никогда.

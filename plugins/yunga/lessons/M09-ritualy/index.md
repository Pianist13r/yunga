# M09 «Ритуалы» — свой `/wrap` и вход в новую сессию

**Этап:** 2 «Матрос». **Зависит от:** M07 (память, капсула), M08 (скиллы). **Одна встреча, 20–40 минут.**

## Зачем этот модуль ученику

Закрывать работу ученик уже умеет по кускам: попросить «запомни» (M07), поправить `CLAUDE.md` (M05), заполнить капсулу (M07 s3). Проблема в другом — каждый раз это разные действия, и без списка перед глазами что-то забывается: то капсула не обновилась, то договорённость осталась только в разговоре. После этого модуля у него есть **свой** скилл `/wrap`, который проходит все домашние дела разом, одной командой, — и фраза, с которой он сам открывает следующую сессию, не начиная объяснять всё заново.

Ключевое слово — **сам**: скилл запускает и закрывает ученик, не я. У опытных пользователей собственный ритуал закрытия обычно уже есть — здесь он просто получает форму, которую можно повторить.

## Из чего состоит

| Шаг | О чём | Время |
|---|---|---|
| `s1.md` | Свой `/wrap` из заготовки: ручной скилл на три-четыре шага | ~15 мин |
| `s2.md` | Закрыть сессию самому на настоящей задаче — гейт модуля | ~10 мин |
| `s3.md` | Фраза для входа в новую сессию и короткая ежемесячная сверка | ~10 мин |

## Что остаётся у ученика

Личный скилл `~/.claude/skills/wrap/SKILL.md` (или уже бывший у ученика скилл закрытия под своим именем — тогда команда его), вызываемый только вручную · опыт, что закрытие сессии — это его команда, а не моё решение · капсула с сегодняшней датой · фраза для входа в следующую сессию · строка в журнале с датой следующей ежемесячной сверки.

Личный скилл работает во вкладке Code на этом компьютере; во вкладке Cowork и в облачных сессиях свои скиллы из `~/.claude/skills` не видны.

## Что ведущий читает до начала

- `${CLAUDE_PLUGIN_ROOT}/templates/skill-wrap/SKILL.md` — заготовка ритуала, уже почищенная: шапка разбирается, `disable-model-invocation: true` стоит;
- `${CLAUDE_PLUGIN_ROOT}/templates/capsule.md` — та же заготовка капсулы, что в M07 s3: сегодня её не заводим заново, а обновляем;
- `${CLAUDE_PLUGIN_ROOT}/procedures/consent.md` — протокол правки: на шаге 1 применяется к новому файлу (без бэкапа — копировать нечего), на шаге 2 — к правкам существующих файлов;
- `${CLAUDE_PLUGIN_ROOT}/procedures/gate.md` — кондуктор шага и формат `decisions.md`;
- `${CLAUDE_PLUGIN_ROOT}/procedures/surface-steps.md` — как в приложении выбирается папка (Project folder): на шаге 3 сессия впервые открывается не из журнала, а из папки задачи;
- Термины «ручной вызов», `disable-model-invocation`, `context: fork` уже введены текстом урока в M08, здесь только опираемся на них — отдельных статей на них в `reference/glossary.md` нет.

**Реплики в кавычках — образец формулировки, а не сценарий слово в слово** (`lessons/catalog.md`): смысл и простота обязательны, форма — на усмотрение ведущего. Исключение — помеченное словом **дословно**.

## Чего в этом модуле не делаем

**Не ставим хуки** — автоматическое напоминание о `/wrap` без участия ученика появится в M12, здесь об этом только одна фраза. **Не пишем полный чек-лист обслуживания** — это M14; здесь заводится только короткая строка «раз в месяц сверить» с датой. **Не используем `@import`** для капсулы или журнала: причина та же, что в M05 s3 — файл грузился бы целиком и всегда, а не тогда, когда нужен. **Не встраиваем автозапуск.** `disable-model-invocation` остаётся `true` — вызвать скилл может только ученик, не я. Отдельно: `context: fork` в него не идёт — ритуалу нужна история этого разговора, а не отдельная комната без неё.

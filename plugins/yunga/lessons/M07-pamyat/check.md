# M07 — задание проверяющему (служебный файл)

Читает `agents/course-checker.md`. Курс вызывает его с **одним** разделом и подставляет полные пути вместо `<журнал>` (папка журнала ученика), `<память>` (папка памяти проекта, `~/.claude/projects/<project>/memory/`) и `<проект>` (рабочая папка ученика).

**Оговорки ко всем разделам.**
1. Абсолютные пути с именем учётной записи ученика — ожидаемы, это не находка. Находка — путь за пределами `<журнал>`, `<память>` и `<проект>`.
2. **Содержимое личной памяти ученика не цитировать никогда** — ни значения фактов, ни их фрагменты, ни куски текста файла-темы. В отчёте называется только место (путь) и факт наличия записи («в файле-теме есть строка, обновлённая после начала занятия» — можно; сам текст строки — нельзя).
3. Наблюдаемое срабатывание (вспомнил ли я факт в новой сессии) файлом не проверяется — это подтверждает курс в моменте, а не проверяющий. Отсутствие такой записи в отчёте не пишется.

## Шаг 1

- **улика:** `<журнал>/journal/` — файл занятия за дату шага
- **критерии:**
  1. в файле назван полный путь к `<память>/MEMORY.md` и к файлу-теме рядом с ним;
  2. записи о правках нет — на этом шаге их быть не должно; строка вида `CH-NNN`, датированная этим шагом, — находка;
  3. файл занятия не содержит текста самого запомненного факта дословно — только упоминание, что он есть и где лежит (см. оговорку 2).
- **бюджет:** файл занятия не больше 3 КБ.

## Шаг 2

- **улика:** файл-тема из `<память>`, `<журнал>/changes.md`, папка копии в `<журнал>/backups/`
- **критерии:**
  1. время изменения файла-темы новее времени снятой копии — значит правка после бэкапа состоялась (сравнивать по времени/размеру файла, не по содержимому);
  2. в `<журнал>/changes.md` есть строка `CH-NNN` про это изменение: дата с поясом, путь к файлу-теме, что изменено (в общих словах — «уточнён факт про проект», без цитаты), путь к копии, как вернуть, как проверено;
  3. папка копии из этой строки существует, в ней `manifest.md` с четырьмя столбцами (файл, откуда, байт, sha256) и полным путём к оригиналу;
  4. `CH-NNN` этого шага отличается от `CH-NNN` шага 1 (на шаге 1 правок не было, но на будущее — номера не должны совпадать при повторной проверке модуля).
- **бюджет:** в описи — не больше 40 строк.
- **неясно (не угадывать):** если у файла-темы нет строки-пометки о времени правки в самом верху — это не находка, а особенность файла; проверка идёт по времени изменения файла в файловой системе.

## Шаг 3

- **улика:** файл капсулы в `<проект>` (по `templates/capsule.md`), `<журнал>/decisions.md`
- **критерии:**
  1. файл капсулы в `<проект>` существует и структурно повторяет заголовки заготовки (`Что хотели сделать`, `Что сделано`, `Что проверено и как`, `Что НЕ проверено`, `Где остановились`) — хотя бы часть разделов заполнена не шаблонными плейсхолдерами вида `[впиши…]`;
  2. в `<журнал>/decisions.md` есть строка, описывающая, где дом у памяти, у журнала курса и у `CLAUDE.md` — по формату из `procedures/gate.md` (дата+пояс | решение | почему | где видно | куда на выпуске);
  3. текст капсулы не пересказывает содержимое личной памяти ученика дословно — проверяющий это не оценивает по сути задачи, только по структуре (см. оговорку 2 — как способ не выйти за роль).
- **бюджет:** файл капсулы — на экран, ориентир из заготовки ≤2 КБ; строка в `decisions.md` — одна.
- **неясно:** если у ученика ещё нет отдельной сквозной задачи для капсулы (редкий случай — модуль идёт после M05, задача обычно уже есть) — это `НЕЯСНО` с вопросом «на чём заполняли капсулу», а не `FAIL`.
